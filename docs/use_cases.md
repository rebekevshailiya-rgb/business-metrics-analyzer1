# Use Case — Business Metrics Analyzer

Практическое занятие № 2. Компания: ООО «Ритейл-Аналитика».

## Роли и права доступа

Распределение ролей в учебной модели основано на восьми User Stories проекта. Четыре актора из методички сохранены; дополнительно указан руководитель отдела, который присутствует в US-04 и US-07.

| Актор | Область данных | Варианты использования |
|---|---|---|
| Коммерческий директор | Все отделы | Просмотр дашборда KPI, формирование отчёта, экспорт отчёта в Excel. |
| Руководитель отдела | Только свой отдел | Просмотр дашборда KPI, формирование отчёта, экспорт отчёта в Excel, получение уведомлений о снижении KPI своего отдела. |
| Менеджер по продажам | Только свои сделки | Просмотр дашборда KPI, загрузка данных о своих продажах. |
| Аналитик | Все отделы | Просмотр дашборда KPI, формирование отчёта, загрузка данных, экспорт отчёта в Excel, настройка правил расчёта метрик. |
| Администратор системы | Учётные записи, роли и области доступа | Управление пользователями. Финансовые данные не доступны только на основании роли администратора. |

Во всех сценариях с данными продаж пользователь должен быть авторизован. Сервер проверяет права доступа при каждом запросе. Обход ограничений через изменение URL или параметров запроса не допускается.

Для первого спринта учётные записи и роли создаются при первичной настройке. Административный интерфейс относится к US-05 и реализуется позднее.

## Связь диаграммы и User Stories

| Вариант использования | User Story | Примечание |
|---|---|---|
| Просмотр дашборда KPI | US-01 | Директор видит все отделы, руководитель — свой отдел, менеджер — свои продажи, аналитик — все отделы. |
| Формирование отчёта | US-02 | Основной актор истории — аналитик. Директор и руководитель также формируют отчёты в пределах своих прав, согласно общей модели ролей в требованиях. |
| Загрузка данных о продажах | US-03 | Менеджер загружает свои сделки, аналитик — данные всех отделов, как предусмотрено бизнес-требованиями. |
| Экспорт отчёта в Excel | US-04 | Сохраняется роль руководителя отдела из истории. Директору и аналитику также предоставляется экспорт доступных им отчётов. |
| Управление пользователями | US-05 | Только администратор. |
| Настройка правил расчёта метрик | US-06 | Аналитик; планируется в третьем спринте. Конкретные настраиваемые параметры требуют уточнения. |
| Получение уведомлений о снижении KPI | US-07 | Руководитель отдела; планируется в третьем спринте. |

US-08 «Мобильная версия» описывает доступ с другого устройства к уже указанным сценариям. Она не требует отдельного актора или отдельного варианта использования и не входит в текущий релиз.

Диаграмма отражает как функции MVP, так и планируемые функции. Она не означает, что все функции уже реализованы. Для читаемости PNG объединяет пять отдельных представлений — по одному для каждой роли. Повторение одного UC-ID в разных блоках обозначает один и тот же вариант использования, а не разные функции. PUML содержит те же пять представлений; точное расположение элементов при его автоматическом рендеринге может отличаться от PNG с вручную выровненными элементами.

## UC-02. Формирование отчёта

| Поле | Значение |
|---|---|
| Название | Формирование отчёта. |
| Связанная User Story | US-02. |
| Основной актор | Аналитик. |
| Другие акторы | Коммерческий директор, руководитель отдела — в пределах своей области доступа. |
| Предусловие | Пользователь авторизован и имеет право формировать отчёты. В системе доступен источник данных; наличие сделок в выбранном периоде проверяется в ходе сценария. |
| Основной поток | 1. Пользователь открывает раздел отчётов.<br>2. Выбирает период и допустимые фильтры.<br>3. Нажимает «Сформировать».<br>4. Система проверяет права и корректность периода.<br>5. Система рассчитывает KPI по разрешённым пользователю данным.<br>6. Система показывает таблицу показателей по доступным отделам и график выручки по месяцам, выбранный период и время последней успешной загрузки.<br>7. Пользователь просматривает результат. |
| Альтернативный поток A1: нет данных | После шага 4 система не находит подходящих сделок, показывает «Нет данных за выбранный период» и не строит таблицу и график. Предыдущий отчёт не выдаётся за результат нового периода. |
| Альтернативный поток A2: неправильный период | Дата начала позже даты окончания. Система показывает ошибку на русском языке и предлагает исправить период; отчёт не формируется. |
| Альтернативный поток A3: недопустимая область данных | Пользователь запрашивает чужой отдел или сделки вне своей области доступа. Система отклоняет запрос и не раскрывает запрещённые данные. |
| Постусловие при успехе | Отчёт сформирован; таблица и график соответствуют выбранным фильтрам и согласованным формулам KPI. Экспорт доступен пользователям с соответствующим правом после реализации US-04. |
| Постусловие при альтернативном завершении | Новый отчёт не сформирован; пользователь получил причину отказа или отсутствия результата, исходные данные не изменены. |

## UC-03. Загрузка данных о продажах

| Поле | Значение |
|---|---|
| Название | Загрузка данных о продажах. |
| Связанная User Story | US-03. |
| Основной актор | Менеджер по продажам. |
| Другой актор | Аналитик, имеющий право загружать данные всех отделов. |
| Предусловие | Пользователь авторизован и имеет право загрузки. Подготовлен файл CSV или XLSX; корректность файла и его соответствие области доступа проверяются в ходе сценария. |
| Основной поток | 1. Пользователь открывает загрузку данных.<br>2. Выбирает файл с данными допустимой для него области.<br>3. Нажимает «Загрузить».<br>4. Система проверяет формат, обязательные поля, типы значений, идентификаторы сделок и права пользователя.<br>5. Система сохраняет корректные новые данные целиком, без частичной загрузки.<br>6. Система показывает количество добавленных сделок и дату и время успешной загрузки. |
| Альтернативный поток A1: ошибки данных | После шага 4 система отклоняет файл целиком и показывает номера строк и причины ошибок. Если отсутствует обязательный столбец, система указывает название отсутствующего столбца. Ранее загруженные данные не изменяются. |
| Альтернативный поток A2: повторная загрузка | Весь набор уже существует и его значения не менялись. Система сообщает, что данные уже загружены; сделки не дублируются, суммы и KPI не меняются. |
| Альтернативный поток A3: чужие сделки | Менеджер загружает сделки другого менеджера. Система отклоняет файл целиком, сообщает об ограничении доступа и не сохраняет данные. |
| Альтернативный поток A4: сбой сохранения | Во время записи происходит сбой. Система отменяет изменения этой загрузки, сохраняет прежнее состояние данных и сообщает, что загрузка не завершена. |
| Постусловие при успехе | Данные сохранены без дублей и доступны для расчёта KPI в пределах прав пользователей. Время успешной загрузки обновлено. |
| Постусловие при повторной загрузке | Существующий набор остаётся неизменным; пользователю показано сообщение о повторе. |
| Постусловие при отказе или сбое | Ни одна строка отклонённого файла не добавлена; ранее загруженные данные остаются неизменными. |
