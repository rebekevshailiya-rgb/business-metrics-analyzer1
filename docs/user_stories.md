# User Stories — Business Metrics Analyzer

### US-01. Просмотр дашборда KPI

**Как** коммерческий директор,
**я хочу** видеть на главной странице дашборд с четырьмя ключевыми показателями эффективности (KPI): выручка, средний чек, конверсия, рентабельность, с фильтрами по периоду, отделу и менеджеру,
**чтобы** оперативно оценивать состояние продаж без формирования отчётов вручную.

**Приоритет:** Must have
**Оценка:** 5 Story Points
**Спринт:** 1

**Критерии приёмки:**

**AC-01.1**
Given: пользователь авторизован как коммерческий директор, данные о продажах загружены,
When: пользователь открывает главную страницу,
Then: отображается дашборд с KPI: выручка, средний чек, конверсия, рентабельность по всем отделам.

**AC-01.2**
Given: данные о продажах загружены (до 10 000 сделок, до 10 одновременных пользователей),
When: пользователь выбирает диапазон дат и отдел,
Then: KPI пересчитываются и обновляются на дашборде в течение 3 секунд.

**AC-01.3**
Given: за выбранный период нет завершённых продаж,
When: пользователь открывает дашборд,
Then: KPI с нулевым знаменателем отображаются как «Не определён», ошибка деления на ноль не возникает.

**AC-01.4**
Given: пользователь не авторизован,
When: пользователь открывает главную страницу,
Then: система перенаправляет его на страницу входа и не показывает данные.

### US-02. Формирование отчёта

**Как** аналитик,
**я хочу** формировать отчёт за выбранный период с таблицей показателей по отделам и графиком выручки по месяцам,
**чтобы** сравнивать результаты отделов и готовить аналитику без ручных расчётов в Excel.

**Приоритет:** Must have
**Оценка:** 8 Story Points
**Спринт:** 1

**Критерии приёмки:**

**AC-02.1**
Given: пользователь авторизован как аналитик, данные за период загружены,
When: пользователь выбирает период и нажимает «Сформировать»,
Then: система отображает таблицу показателей и график выручки по месяцам.

**AC-02.2**
Given: за выбранный период нет данных,
When: пользователь нажимает «Сформировать»,
Then: система выводит сообщение «Нет данных за выбранный период», таблица и график не строятся.

**AC-02.3**
Given: у пользователя есть доступ к нескольким отделам,
When: пользователь формирует отчёт за один период,
Then: в таблице показаны показатели каждого доступного отдела за этот период для сравнения.

### US-03. Загрузка данных о продажах

**Как** менеджер по продажам,
**я хочу** загрузить файл CSV или XLSX с данными своих сделок,
**чтобы** данные попали в систему без ручного сведения таблиц аналитиком.

**Приоритет:** Must have
**Оценка:** 5 Story Points
**Спринт:** 1

**Критерии приёмки:**

**AC-03.1**
Given: пользователь авторизован, файл содержит все обязательные поля и корректные значения,
When: пользователь загружает файл,
Then: данные сохраняются, а система показывает дату и время последней успешной загрузки.

**AC-03.2**
Given: в файле отсутствует обязательное поле или есть повторяющийся идентификатор сделки,
When: пользователь загружает файл,
Then: файл отклоняется целиком, система показывает номера строк с ошибками и причины, ранее загруженные данные не изменяются.

**AC-03.3**
Given: набор данных уже был успешно загружен,
When: пользователь повторно загружает тот же файл,
Then: продажи не дублируются, значения KPI не меняются.

### US-04. Экспорт отчёта в Excel

**Как** руководитель отдела,
**я хочу** экспортировать сформированный отчёт в файл XLSX,
**чтобы** использовать его на совещаниях и отправлять коллегам.

**Приоритет:** Should have
**Оценка:** 3 Story Points
**Спринт:** 2

**Критерии приёмки:**

**AC-04.1**
Given: отчёт за выбранный период сформирован,
When: пользователь нажимает «Экспорт в Excel»,
Then: скачивается файл XLSX с таблицей отчёта и указанием выбранного периода.

**AC-04.2**
Given: пользователь имеет доступ только к своему отделу,
When: пользователь экспортирует отчёт,
Then: в файле содержатся данные только его отдела.

### US-05. Управление пользователями

**Как** администратор системы,
**я хочу** создавать и блокировать учётные записи и назначать роли и область доступа,
**чтобы** каждый пользователь видел только те данные, которые разрешены ему по должности.

**Приоритет:** Should have
**Оценка:** 5 Story Points
**Спринт:** 2

**Критерии приёмки:**

**AC-05.1**
Given: администратор авторизован,
When: администратор создаёт учётную запись, назначает роль и область доступа,
Then: пользователь может войти в систему и видит только данные своей области доступа.

**AC-05.2**
Given: учётная запись пользователя активна,
When: администратор блокирует её,
Then: пользователь не может войти в систему, ему показывается сообщение о блокировке.

**AC-05.3**
Given: пользователь имеет роль «Менеджер по продажам»,
When: пользователь открывает дашборд,
Then: отображаются только его собственные продажи.

### US-06. Настройка метрик

**Как** аналитик,
**я хочу** настраивать правила расчёта KPI (например, учёт возвратов, скидок и налогов),
**чтобы** показатели соответствовали согласованным с заказчиком правилам без доработки кода.

**Приоритет:** Could have
**Оценка:** 8 Story Points
**Спринт:** 3

**Критерии приёмки:**

**AC-06.1**
Given: пользователь авторизован как аналитик,
When: пользователь изменяет правило расчёта и сохраняет его,
Then: KPI на дашборде и в отчётах пересчитываются по новому правилу.

**AC-06.2**
Given: пользователь ввёл некорректное значение параметра,
When: пользователь пытается сохранить настройки,
Then: система показывает сообщение об ошибке, прежние настройки остаются без изменений.

---

### US-07. Уведомления о KPI

**Как** руководитель отдела,
**я хочу** получать уведомление, когда KPI выходит за заданное пороговое значение,
**чтобы** быстро реагировать на снижение показателей.

**Приоритет:** Could have
**Оценка:** 3 Story Points
**Спринт:** 3

**Критерии приёмки:**

**AC-07.1**
Given: пользователь задал порог для рентабельности своего отдела, равный 15%,
When: после загрузки данных рентабельность отдела составляет 12%,
Then: в системе отображается уведомление о выходе показателя за порог.

**AC-07.2**
Given: пользователь задал порог для рентабельности, равный 15%,
When: после загрузки данных рентабельность отдела составляет 18%,
Then: уведомление не отображается.

### US-08. Мобильная версия

**Как** менеджер по продажам,
**я хочу** открывать дашборд на смартфоне,
**чтобы** смотреть свои показатели вне офиса.

**Приоритет:** Won't have
**Оценка:** 13 Story Points
**Спринт:** –

**Критерии приёмки:**

**AC-08.1**
Given: пользователь открывает систему на смартфоне с шириной экрана 360 px,
When: пользователь открывает дашборд,
Then: все четыре KPI отображаются без горизонтальной прокрутки.

**AC-08.2**
Given: пользователь вошёл со смартфона под своей учётной записью,
When: пользователь открывает данные,
Then: ему доступны те же данные и права, что и в версии для компьютера.

## Проверка по критериям INVEST

INVEST: Independent (независимая), Negotiable (обсуждаемая), Valuable (ценная), Estimable (оцениваемая), Small (небольшая), Testable (проверяемая).

| US | I | N | V | E | S | T | Комментарий |
|---|---|---|---|---|---|---|---|
| US-01 | ± | + | + | + | + | + | Для отображения данных нужна US-03, поэтому порядок в спринтах: сначала загрузка. |
| US-02 | ± | + | + | + | ± | + | Зависит от US-03. 8 Story Points — верхняя граница для одного спринта; при необходимости делится на таблицу и график. |
| US-03 | + | + | + | + | + | + | Не зависит от других историй. |
| US-04 | ± | + | + | + | + | + | Зависит от US-02. |
| US-05 | + | + | + | + | + | + | Независима. |
| US-06 | + | + | + | + | ± | + | 8 Story Points; при необходимости делится по типам правил (возвраты, скидки, налоги). |
| US-07 | ± | + | + | + | + | + | Зависит от US-03 и расчёта KPI из US-01. |
| US-08 | + | + | + | ± | ± | + | 13 Story Points и не входит в текущий релиз; перед включением в релиз нужно разделить на более мелкие истории и повторно оценить. |

Обозначения: «+» — критерий выполнен, «±» — выполнен с оговоркой (см. комментарий).
