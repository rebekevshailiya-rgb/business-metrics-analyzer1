# ADR-001. Выбор архитектурного стиля

## Статус

Принято в учебной архитектурной модели; реализация запланирована.

## Контекст

Команда из трёх человек развивает консольный прототип до веб-приложения. Нужны быстрый выпуск и изоляция бизнес-правил.

## Решение

Слоистый модульный монолит с инверсией зависимостей. API и worker из одного кода/образа; сервисы предметных областей остаются модулями.

## Альтернативы

Монолит без слоёв: меньше начальных интерфейсов, но связность. Микросервисы: независимые релизы, но сетевые и эксплуатационные затраты. Serverless: инфраструктура управляется провайдером, но batch-импорт и согласование транзакций сложнее.

## Последствия

Единый выпуск, проще локальные транзакции и тесты. Дополнительные интерфейсы требуют дисциплины. При выделении сервиса потребуется отдельный контракт и миграция данных.
