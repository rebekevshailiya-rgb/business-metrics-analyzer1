# ADR-003. JWT и актуальные права пользователя

## Статус

Принято в учебной архитектурной модели; реализация запланирована.

## Контекст

ПЗ № 4 прямо требует JWT. Нужны API/браузер, роли, отзыв доступа после блокировки.

## Решение

Короткоживущий access JWT, проверка подписи/exp/issuer/audience и актуального статуса пользователя; refresh с ротацией и хранением хеша. Scope применяется на сервере и включается в ключ кэша.

## Альтернативы

Серверные сессии: проще немедленный отзыв, но не выполняют требование JWT сами по себе. Долгоживущий JWT без проверки статуса: меньше запросов, но заблокированный пользователь сохраняет доступ.

## Последствия

JWT не шифрует payload и не заменяет авторизацию. Дополнительное состояние refresh/блокировок уменьшает stateless-эффект, но необходимо для безопасности.
