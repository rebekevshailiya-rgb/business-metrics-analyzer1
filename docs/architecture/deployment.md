# Развёртывание: узлы и ресурсы

Проектная топология для одного облачного Linux-узла, Docker Compose и закрытой внутренней сети. Это спецификация, не инструкция о якобы выполненном запуске. Worker и API используют один образ приложения, но разные процессы.

| Узел | ПО / образ (семейство) | Начальный бюджет | Назначение |
|---|---|---|---|
| Reverse proxy | Nginx stable, digest фиксируется | 0.5 CPU, 256 MiB | TLS, статический UI, проксирование HTTP, лимиты загрузки |
| API | bma-app, Python 3.12+, FastAPI/Uvicorn | 1 CPU, 1 GiB | HTTP, роли, постановка заданий, чтение KPI |
| Worker | тот же bma-app, Celery | 2 CPU, 2 GiB | Импорт, агрегирование, XLSX/PDF, SMTP |
| PostgreSQL | PostgreSQL 16.x, актуальный patch/digest при запуске | 2 CPU, 2 GiB + диск | Продажи, staging, задания, outbox, аудит, агрегаты |
| Redis cache | Redis 7.x, точный выпуск фиксируется | 0.5 CPU, 512 MiB | Кэш с TTL и допустимым вытеснением |
| Redis broker | отдельный Redis 7.x | 0.5 CPU, 512 MiB | Очередь, persistence и noeviction; outbox для восстановления отправки |
| Хранилище | облачный S3 или MinIO в учебной среде | Квота от 10 GiB; MinIO: 0.5 CPU, 512 MiB | Исходные файлы и готовые отчёты, lifecycle |

Бюджеты предварительные, не результаты профилирования. Для варианта с локальным MinIO суммарно около 7 CPU и 6.75 GiB лимитов контейнеров, плюс ОС/буферы/дисковый запас: исходный кандидат VM 8 vCPU, 12–16 GiB RAM. Точный диск зависит от строк, индексов, staging и срока хранения, а не только числа записей. В облачном S3 память MinIO на VM не требуется.

| Соединение | Протокол |
|---|---|
| Браузер → Nginx | HTTPS 443 |
| Nginx → API | HTTP 8000 только во внутренней сети |
| API / worker → PostgreSQL | PostgreSQL 5432; TLS для удалённой БД |
| API / worker → Redis | Redis 6379 во внутренней сети, ACL; TLS при пересечении узлов |
| API / worker → хранилище | S3 API через HTTPS; локальный MinIO в закрытой сети |
| Worker → SMTP | SMTP submission с STARTTLS 587 или TLS 465 по настройкам провайдера |
| Worker → источник | HTTPS; CSV/XLSX загружает браузер через API |

Публично открывается только HTTPS Nginx; БД, очередь и хранилище не публикуются в Интернет. Секреты передаются через секрет-хранилище/окружение, `.env` с секретами не коммитится. Разные учётные записи сервисов, закрытый bucket, ограниченный CORS, health/readiness-проверки и graceful shutdown.

PostgreSQL и broker имеют постоянные volumes; для БД задаётся расписание резервного копирования и проверяется восстановление. Предлагаемые RPO 24 ч/RTO 4 ч требуют согласования, это не гарантированная доступность. Нужны метрики p95 HTTP, очереди, ошибок импорта и БД, централизованные логи без токенов и контроль свободного диска.
