# План защиты: 5 минут

Это текст для выступления по целевой архитектуре, без заявления о развёрнутом веб-приложении.

1. **0:00–0:40. Задача и драйверы.** BMA автоматизирует отчёты о продажах. В ПЗ № 4 учитываем миллион строк, ≤3 с для дашборда, JWT/роли и облачный Docker. Существующий main.py пока консольный.
2. **0:40–1:20. Контекст.** Пять ролей с разными областями доступа; источник продаж и почтовый провайдер — внешние системы.
3. **1:20–2:10. Контейнеры.** Браузер, API и worker, PostgreSQL, раздельные Redis для кэша и очереди, S3. API и worker из одного кода; Auth/KPI/ReportService — модули монолита.
4. **2:10–3:00. Компоненты.** HTTP → сценарии → Domain/порты. Инфраструктура реализует порты. Пример: импорт сначала валидирует staging, затем публикует набор атомарно. Область доступа проверяется до кэша.
5. **3:00–3:50. Развёртывание.** Публичен Nginx; БД/Redis закрыты. Один узел дешевле, но остаётся точкой отказа; бюджеты ресурсов предварительные.
6. **3:50–5:00. Паттерны и ADR.** Repository/UoW отделяют БД и транзакции; Strategy задаёт общий интерфейс KPI. Приняты четыре ADR. Шесть тестов проверяют примеры, но SLA и облачное развёртывание ещё нужно проверять после реализации.
